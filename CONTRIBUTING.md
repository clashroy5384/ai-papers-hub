# Contributing to AI Papers Hub

Thanks for helping build this! The goal is a **high-signal, low-noise** directory — every entry should genuinely help someone working with AI papers.

## What we accept

✅ **Yes:**
- Free resources, or resources with a meaningful free tier (clearly noted).
- Active, maintained tools/sites/lists.
- Resources that fill a real gap in the hub.
- Well-known canonical resources we might have missed.

❌ **No:**
- Paywalled-only resources (unless truly essential).
- Dead links or unmaintained projects (last commit > 3 years for code repos).
- Aggregators that mostly serve ads or scraped content.
- Self-promotion of low-value content.
- Duplicates of resources already listed.
- AI-generated link dumps without curation.

## How to contribute

### Adding a single resource

1. Fork the repo.
2. Open `README.md` and find the most appropriate section.
3. Add your resource using the existing format:
   ```markdown
   - **[Resource Name](https://link)** — One-sentence description of what makes it useful.
   ```
4. Keep alphabetical or logical order where the section uses it.
5. Open a PR with a short justification: *why* this belongs here.

### Suggesting a new section

If you think a whole category is missing, open an **issue** first to discuss before submitting a PR. This keeps the structure coherent.

### Reporting a problem

- **Dead link?** Open an issue with the title `[Dead link] <Resource Name>`.
- **Outdated info?** Same format: `[Outdated] <Resource Name>`.
- **Resource turned bad** (now paywalled, abandoned, hostile design)? Open an issue, we'll discuss removal.

## Style guide

- **Descriptions:** one sentence, max ~15 words. Say what it is and why it's useful — not what the author wishes it were.
- **No marketing language.** No "revolutionary," "game-changing," "best-in-class." Just describe it.
- **Free tier?** Note it explicitly: `(free tier)` or `(free for academic use)`.
- **Linking:** Use the canonical URL (the project's own site, not a third-party mirror).
- **Capitalization:** Match the resource's own branding (e.g., `arXiv`, not `Arxiv`).

## Review process

PRs are typically reviewed within a week. We may:
- Merge as-is.
- Request edits to the description or placement.
- Close with explanation if it doesn't fit the criteria above.

Don't take a closed PR personally — we close things that don't fit the hub's bar, not because the resource is bad.

## Code of Conduct

Be respectful. Disagree on substance, not people. We follow the [Contributor Covenant](https://www.contributor-covenant.org/version/2/1/code_of_conduct/).
